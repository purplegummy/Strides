\section{Prerequisites (Required Before Setup)}

Ensure the following tools are installed \textbf{before} cloning the repository.

\begin{itemize}
    \item \textbf{Node.js (LTS)} — version 18 or higher
    \item \textbf{npm} (included with Node.js)
    \item \textbf{Git}
    \item \textbf{VS Code} (recommended editor)
\end{itemize}

Verify installations:
\begin{lstlisting}[language=bash]
node -v
npm -v
git --version
\end{lstlisting}

If any command fails, install the missing tool before continuing.

\section{First-Time Project Setup}

These steps are completed \textbf{once per machine}.

\begin{enumerate}
    \item \textbf{Clone the Repository}
\begin{lstlisting}[language=bash]
git clone https://github.com/purplegummy/Strides.git
cd Strides
\end{lstlisting}

    \item \textbf{Install Dependencies}
\begin{lstlisting}[language=bash]
npm install
\end{lstlisting}

    \item \textbf{Environment Variables}

    Create a file named \texttt{.env} in the project root.

    Check slack for the database URL and add:
\begin{lstlisting}
DATABASE_URL="..."
\end{lstlisting}

\textbf{Never commit this file.}

    \item \textbf{Generate Prisma Client}
\begin{lstlisting}[language=bash]
npx prisma generate
\end{lstlisting}

    \item \textbf{Verify Setup}
\begin{lstlisting}[language=bash]
npm run dev
\end{lstlisting}

Open \texttt{http://localhost:3000}. If the app loads, setup is complete.
\end{enumerate}

\section{Git Workflow Rules (Non-Negotiable)}

\begin{itemize}
    \item Never push directly to \texttt{main}
    \item Always work on a feature branch
    \item Never merge broken code
\end{itemize}

\subsection*{Standard Feature Workflow}

\begin{enumerate}
    \item Sync with main:
\begin{lstlisting}[language=bash]
git checkout main
git pull origin main
\end{lstlisting}

    \item Create and switch to a feature branch:
\begin{lstlisting}[language=bash]
git checkout -b feature-my-feature
\end{lstlisting}

    \item Code and test locally

    \item Commit changes:
\begin{lstlisting}[language=bash]
git add .
git commit -m "Clear description of work"
\end{lstlisting}

    \item Push branch:
\begin{lstlisting}[language=bash]
git push -u origin feature-my-feature
\end{lstlisting}

    \item Open a Pull Request and wait for approval
\end{enumerate}

\section{Critical Concept: How Prisma Sees the World}

\begin{quote}
Prisma compares your \texttt{schema.prisma} file directly to the \textbf{live remote database}.  
Anything missing in your local schema is treated as something to DELETE.
\end{quote}

\textbf{Git branches do NOT isolate database changes.}  
The database is shared global state.

\section{Prisma Commands Explained}

\subsection*{\texttt{npx prisma generate}}

\textbf{What it does:}
\begin{itemize}
    \item Generates the Prisma Client used by the app
    \item Does NOT modify the database
\end{itemize}

\textbf{When to run:}
\begin{itemize}
    \item After pulling new code
    \item After any schema change
\end{itemize}

\textbf{Risk level:} Safe at all times

\subsection*{\texttt{npx prisma db push}}

\textbf{What it does:}
\begin{itemize}
    \item Forces the database schema to match your local \texttt{schema.prisma}
    \item Deletes anything present in the database but missing locally
\end{itemize}

\textbf{Key warning:}
\begin{quote}
Prisma does not know about Git branches, pull requests, or unfinished features.
\end{quote}

\textbf{Risk level:} High without coordination

\section{The Schema Lock Protocol (MANDATORY)}

\subsection*{The Rule}

\begin{quote}
\textbf{If you modify \texttt{schema.prisma} and run \texttt{db push}, you have locked the database.}
\end{quote}

Until your schema changes are shared or merged:
\begin{itemize}
    \item No one else may safely run \texttt{npx prisma db push}
    \item Other developers may continue coding, but not push schema changes
\end{itemize}

\subsection*{What You MUST Do After a Schema Change}

\begin{enumerate}
    \item Immediately notify the team:
\begin{quote}
``I added a column to \texttt{schema.prisma}. Do not run \texttt{db push} without syncing my changes.''
\end{quote}

    \item Share your schema changes (paste or PR)
    \item Merge as soon as your feature allows
\end{enumerate}

\subsection*{Green Light: Additive Changes}

\textbf{Examples:}
\begin{itemize}
    \item Adding a new table
    \item Adding a new column
\end{itemize}

\textbf{Allowed if and only if:}
\begin{itemize}
    \item The team is aware
    \item Everyone who may run \texttt{db push} has your schema
\end{itemize}

\subsection*{Red Light: Destructive Changes}

\textbf{Examples:}
\begin{itemize}
    \item Renaming fields
    \item Deleting tables or columns
    \item Changing column types
\end{itemize}

\textbf{Protocol:}
\begin{enumerate}
    \item Notify the team
    \item Ensure all work is pushed
    \item Get confirmation
    \item Only then run \texttt{db push}
\end{enumerate}

\subsection*{Yellow Light: Schema Desynchronization}

\textbf{Scenario:}
\begin{itemize}
    \item Developer A runs \texttt{db push} with new columns
    \item Developer B runs \texttt{db push} without them
\end{itemize}

\textbf{Result:}
\begin{quote}
Prisma deletes Developer A's changes.
\end{quote}

\textbf{Correct Fix:}
\begin{enumerate}
    \item Sync schemas manually
    \item Confirm schemas match
    \item Then run \texttt{db push}
\end{enumerate}

\section{Troubleshooting}

\paragraph{App crashes after pulling code}
Run:
\begin{lstlisting}[language=bash]
npx prisma generate
\end{lstlisting}

\paragraph{Prisma warns about deleting data}
Stop immediately. You are missing schema changes.

\paragraph{Merge conflict in \texttt{schema.prisma}}
Manually merge both versions. Never blindly accept changes.
